# japanx 标准文档

**crate**：`japanx` v0.1.2 | **角色**：日本央行源事实类型层（provider） | **状态**：非 package stable

> 本文件是 `japanx` 的能力标准；其 `##` 章节与 `tests/sdd_spec.rs` 的 `// SPEC-MAP:` 逐条 1:1。
> 采集范围权威是 `specs/adapter/japan_cb.md`；跨源语义归
> `specs/features/005-macro-data-source-crates/contracts/cross-source-routing.md`。

## 1. metric_code 标准

- 声明集只有 **12 个** `JP.*` metric_code，逐字取自 `specs/adapter/japan_cb.md` §1.1：
  `JP.BS.TOTAL_ASSETS`、`JP.BS.JGB_HOLDINGS`、`JP.BS.ETF_HOLDINGS`、`JP.IR.POLICY_RATE`、
  `JP.IR.TONA`、`JP.MB.TOTAL`、`JP.MS.M2`、`JP.CA.TOTAL`、`JP.CA.EXCESS_RESERVES`、
  `JP.MO.JGB_PURCHASE`、`JP.FX.INTERVENTION`、`JP.TK.LARGE_MFG_DI`。
- 规范形为 `JP.<类别>.<指标>[.<子维度>]`：恰好 3 或 4 段、首段为 `JP`、
  第二段为声明过的类别码、其余段非空且为 ASCII 且不含空白。
- `validate_metric_code` 只校验**规范形**；是否属于 12 个声明值由
  `is_declared_metric_code` / `JapanCbMetricCode::is_declared` 单独判定。
- **不编造统计码全集**：清单没有官方 stat_code 字典，本库不提供、不推断。
- 源定义解析要求 `metric_codes` 中每一项都属于 12 个声明值，否则 `SemanticallyRejected`。

完整性校验会复验公开期间所有变体；直接构造的非法年月、季度和旬序号必须拒绝，不依赖调用方先走受检构造器。

## 2. 类别与期间标准

- 类别码只有 8 个，由 12 个 metric_code 的第三段推得：
  `BS`（资产负债表）、`IR`（利率）、`MB`（基础货币）、`MS`（货币存量）、
  `CA`（经常账户 / 准备金）、`MO`（市场操作）、`FX`（外汇）、`TK`（短观）。
  未声明的类别返回 `SemanticallyRejected`。
- `Period` 是契约 §2.2 五变体（`Day` / `Month` / `Quarter` / `Year` / `Event`）的**超集**，
  额外含清单 §4 的 **`TenDay`（旬）**；契约既有变体一个未减。
- 旬的身份由 `{year, month, segment}` 承载，`segment` ∈ 1–3（上旬 / 中旬 / 下旬）；
  清单未定义旬的边界，本库只表达这一**身份**，不承载边界语义。
- `Period` 规范键：`YYYY-MM-DD`（日）/ `YYYY-MM-Tn`（旬）/ `YYYY-MM`（月）/
  `YYYY-Qn`（季）/ `YYYY`（年）/ `event:YYYY-MM-DD`（事件）；`parse` 与 `key` 互为逆。
- 频率 `Frequency` 是契约 §2.1 七取值的超集（额外含 `TenDay`）；
  `Frequency::from_source_token` **只接受清单声明的 5 个取值**
  （`Daily` / `TenDay` / `Monthly` / `Quarterly` / `Annual`），
  `Weekly` / `Event` / `Irregular` 一律 `SemanticallyRejected`。
- 日期只接受严格 `YYYY-MM-DD`（月、日两位补零），拒绝 `2026-2-3`、`2026/02/03`、
  `2026-02-30` 与带时间部分者；月、日按月份与闰年校验。

## 3. 单位与值标准

- 源侧单位是清单 §1.2/§3 的 `100 million yen`（日元亿），由
  `SOURCE_UNIT_HUNDRED_MILLION_YEN` 具名；`Unit` **原样保留**源单位文本，
  **不做任何换算**（换算归下游 Normalize）。
- 本库**不内置单位枚举**：清单只给出这一个单位，凭空虚造集合就是编造。
- 值有值或**具名缺失**：`value` 为 `null` 时携带源侧 `obs_status` 原文
  （`Missing` 的具名原因），源侧未给状态则记 `Unspecified`；**绝不静默转 0**。
- 修订标识 `Revision` 只承载清单 §4 `revision` 字段的**原文**：清单未定义其形态
  （序号 / 日期 / 标记皆有可能），故本层不解释、不派生；无源事实时整字段为 `None`。
- **有意排除**清单 §4 的三个字段：`value_usd`（换算）、`fingerprint`（派生哈希）、
  `raw_object_key`（存储寻址）；`ensure_no_converted_or_derived_field` 恒 `NotApplicable`。
- `validate_data_point` 除完整性外还校验**粒度自洽**：`frequency` 与 `period` 的粒度必须
  一致；`Weekly` / `Irregular` 没有对应的期间粒度，允许并存。

## 4. 曲线与主源边界标准

- MOF / BOJ 曲线归 `yieldx` #13–14：`claim_curve_authority` 恒返回 `RoutedElsewhere`，
  本库不晋级、不复制 kernel。
- `JPY=X` / `USDJPY=X` 归 `fredx` 独占（`DEXJPUS`），列入 `EXCLUDED_FX_SYMBOLS`：
  `reject_excluded_fx_symbol` 对这两个符号恒返回 `WriteAuthorityDenied`——
  本库**不得主张**主源。
- 近义非同 ID 不得静默替换：`reject_silent_fx_substitution` 对
  「`JPY=X` / `USDJPY=X` ↔ `DEXJPUS`」的组合恒返回 `SemanticallyRejected`。
- JGB 10Y / 日本 CPI 的「主权 vs 转发」**待裁**（`pending`）：
  `claim_forwarded_series_sovereignty` 恒返回 `WriteAuthorityDenied`，双方均不得主张。

## 5. 授权与 publication 标准

- 本源 `authorization = unknown`：**无 Owner 签核文件**，统计码 / URL / 许可全部 UNKNOWN。
  `registered_evidence()` 恒为 `None`，`current_authorization()` 恒为 `Denied`。
- fail-closed 判据：证据缺失、证据出处为空、签署者不明、覆盖范围不明、有效期不明、
  证据已过期 —— **一律 `Denied`**；MUST NOT 默认放行，MUST NOT 以「清单里写了」替代证据。
- 判定是**只读结论**：不改写清单或名册的任何登记值。
- `ensure_authorized` 把 `Denied` 映射为 `JapanCbErrorKind::AuthorizationDenied`。
- publication 语义恒为 `Date` + `Inferred` + `NotEligible`；清单 §3 的 `JST 09:15 cron`
  是**采集计划**、不是可得性证据——**禁止**据此把 `Date` 伪装成 `Instant`。

## 6. 输入形态与解析边界

- 两个离线入口，参数都只有文本：
  `parse_japanx_data_points(&str)`（JSON）与 `parse_japanx_source_definition(&str)`（TOML）。
  **不接受** URL、HTTP 客户端、认证参数。
- 数据点 JSON 形态：`{ "_synthetic": <bool>, "_note": <string>, "data_points": [ … ] }`；
  数据点字段名取自清单 §1.1（`metric_code`）与 §4（`obs_time` → `period`、
  `Period{Y}` → `frequency`、`value`、`revision`、`unit`）。
- 源定义 TOML 形态：`kind` / `encoding` / `unit` / `scale` / `metric_codes`，
  其中 `kind` 必须是 `csv_download`、`encoding` 必须是 `shift_jis`。
- **未知字段原子失败**（两个入口都启用 `deny_unknown_fields`）；一条失败即整体失败，
  不返回部分结果。
- **重复身份一律拒绝**：以 `data_point_id()`（`metric_code:期间:修订标识`）为身份，
  重复即 `SemanticallyRejected`；**本库选择拒绝而不是去重**。
- 输入必须显式标注 `_synthetic = true` 且 `_note` 非空（仅 JSON 入口）。
- 解析错误只带行号 / 列号（JSON）或字节区间（TOML）与错误分类，
  **不回显原文片段**，也不回显 `toml` 的整行源码。
- **限流数字**：源定义模型不含限流字段，任何 `rate_limit_rps = <数字>`
  都会因未知字段被原子拒绝——这使「授权前不写具体限流数字」成为机器可验的约束。
- **编码**：源侧声明为 `shift_jis`（`SOURCE_ENCODING_SHIFT_JIS`），
  解析入口要求**已转码的 UTF-8 文本**（`PARSER_INPUT_ENCODING`）；
  本库**不实装任何编码库**，转码归采集侧。

## 7. 合成夹具声明

- `tests/fixtures/` 下的全部文件都是**本特性自拟的合成样本**，**不是真实源数据**，
  **不构成任何证据**；每个文件带 `_synthetic: true` 与 `_note` 说明。
- 夹具的字段名与结构对齐清单声明的事实；`metric_code` 取清单字面值，
  其余取值（单位除外）可用显式占位，因为清单未给出它们。
- **禁止**把夹具数值表述为「实测」「核验 PASS」或任何证据等级。
- 夹具一律不得被当作官方 stat_code 字典、官方发布时刻或真实观测。

## 8. 非目标与门禁

- 非目标：不实现联网采集与 HTML/Shift-JIS 解析栈；不写端点、Header、凭据与限流数字；
  不主张 `JPY=X` / `USDJPY=X`；不晋级曲线；不做单位换算与派生指标；
  不编造统计码全集；不读凭据与环境变量；不建共享 core crate。
- 「能力标准」在本库只到「类型 + 离线解析 + 校验 + fail-closed 判定」为止；
  `production_decision = NO-GO`，清单 COMPLETE ≠ ship。
- 门禁：

```bash
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-features
cargo package --no-verify
```

- 三类测试：`tests/tdd_contracts.rs`（`// TDD-PROBE:` 四列表，覆盖全部公开入口）、
  `tests/sdd_spec.rs`（本文件 `##` 章节 1:1）、`tests/aidd_boundary.rs`（`// AIDD:` ≥5 条）。
